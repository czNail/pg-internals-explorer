# PostgreSQL Internals Explorer

交互式演示 PostgreSQL 内核各模块的工作机制。

首页以进程、共享内存和文件存储组织运行拓扑。堆页显示在缓冲帧内部，快照显示在 Backend 的本地上下文中。请求、结果返回、共享内存访问、页复制和 WAL 记录采用不同的线型与标签，并显示当前执行者。

可以选择完整链路、读文件、缓存命中、写入提交或后台写回。完整链路依次播放一次读取、一次更新提交和一次后台写回。请求 Q1、结果 R1、页 P8、日志 W1/W2 各自保留身份，页复制完成后更新对应的内存或文件状态。点选模块、快照、页或后台进程可查看说明并进入机制演示。

| 模块 | 演示内容 |
| --- | --- |
| 进程与共享内存 | 连接上限的重载与重启、在线迁移对照、DSM 的挂载与回收 |
| Shared Buffers | 缓冲映射、Pin、Usage count、CLOCK-sweep |
| WAL 与检查点 | WAL 插入、同步提交、数据页写出与文件同步 |
| MVCC | 同一次更新在新旧快照中的可见性 |
| Heap Page / HOT | 行指针、HOT 链、索引入口、页内剪枝 |
| VACUUM | 老快照、索引清理与行指针槽复用 |

全局负载和模块步骤是基于 PostgreSQL 18 的确定性教学模型。首页采用普通堆表、同步 I/O 和本地同步提交的示例路径。模型中的帧数、LSN 和事件间隔均为示例值。模块页链接到相应的 PostgreSQL 文档或源码说明。

## 本地运行

```sh
python3 -m http.server 4173
```

打开 <http://localhost:4173/>。需要 Python 3，无需安装前端依赖。使用 Node.js 执行 `node --test` 可检查事件引用与提交、写页、文件同步的状态边界。

## 发布与主页接入

在仓库的 **Settings → Pages** 中将发布来源设为 **GitHub Actions**。推送到 `main` 时，部署工作流会运行测试并发布静态文件。也可以在 **Actions → Deploy PostgreSQL Internals Explorer** 中手动运行。

页面使用相对资源路径，可部署在项目子路径。项目根目录的 `homepage.json` 声明工具入口，站点上线后，个人主页会在下一次项目目录同步和部署时加入该入口。
